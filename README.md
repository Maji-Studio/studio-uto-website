# Atelier Uto

Studio Uto marketing website: Next.js 16 (App Router), React and TypeScript, with content in Payload CMS 4 (beta) at `/admin`. Styling is plain hand-written CSS (design tokens in `src/styles/global.css`, one stylesheet per component), no CSS framework. Why this stack: [ADR 0003](docs/adr/0003-payload-cms-on-nextjs.md).

Requires Node 24.22.1 or newer, pnpm and Docker (local MongoDB).

## Commands

```bash
pnpm dev                 # starts MongoDB (docker compose, port 27018) and Next on :3060
pnpm build               # needs a reachable MongoDB: pages are pre-rendered from the CMS
pnpm lint
pnpm test

pnpm seed                # loads today's content and images into the local database
pnpm generate:types      # after changing a collection or global
pnpm generate:importmap  # after adding admin components

pnpm env:local           # writes .env.local from 1Password
pnpm env:vercel          # syncs staging → Vercel Preview, production → Vercel Production
pnpm env:check           # reports drift between the templates and 1Password
```

First run: `pnpm env:local` (or copy `.env.example` to `.env` and set `PAYLOAD_SECRET`), `pnpm dev`, create the first user at `/admin` (it becomes admin), then `pnpm seed`.

## Structure

- `src/app/(frontend)`: the five public routes (`/`, `/impressionen/`, `/information/`, `/kontakt/`, `/sketch/`) and the root layout with the cross-document view-transition head scripts.
- `src/app/(payload)`: Payload's admin and API routes, generated by Payload. Don't edit.
- `src/payload`: collections (`users`, `media`, `impressionen`), globals (`site-settings`, `information`), access rules and hooks. Config in `src/payload.config.ts`.
- `src/lib/content`: pages read content only through the getters in `index.ts`, which map Payload documents into the shapes in `types.ts` (see `CONTENT_MODEL.md`).
- `src/components`: page components. Browser behaviour lives in `*.script.ts` modules, started from small `*.client.tsx` components.
- Navigation uses plain `<a href>` links on purpose: the site relies on cross-document View Transitions between full page loads.

## CMS and media

Editors change content at `/admin`. Saving revalidates the pages, so no rebuild is needed. Images are uploaded to the `media` collection. In deployed environments they are stored in the DigitalOcean Space (prefix `media/` in production, `media-<NEXT_PUBLIC_MEDIA_POSTFIX>/` elsewhere) and served from its CDN. Locally, without S3 variables, they go to `media/` on disk.

## Environments and secrets

Secrets live in 1Password (vault `Environment Variables`), never in the repo: one item per environment, `studio-uto-website env local|staging|production`, with fields named like the env vars. `.env.local.tpl` and `.env.tpl` hold `op://` references only. Agents never run `op` themselves.

Setting up the cloud side (Space, MongoDB databases, 1Password items, GitHub secret, Vercel project, first seed) is scripted: `./scripts/setup-infra.sh`.

## Backups

`.github/workflows/backup_mongo_db.yml` and `backup_do_spaces.yml` run daily at 01:30 UTC. They write to the shared backup Space under `studio-uto/mongodb/` and `studio-uto/spaces/` and keep 7 daily, 4 weekly and 12 monthly copies. Credentials come from the 1Password item `studio-uto-website backups` through the `OP_SERVICE_ACCOUNT_TOKEN` repo secret. Restore Mongo with the command at the top of the Mongo workflow.
